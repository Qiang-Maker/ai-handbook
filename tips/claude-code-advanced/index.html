Claude Code 进阶玩法 ​

装好并接入 STJAPI 之后，Claude Code 还藏着一整套进阶能力。用好这几招，它就不只是"对话式补全"，而是能规划、自动化、并行干活的工程队友。

本篇是《从零到驾驭 AI：成长路径》第五阶段的展开。还没安装的先看 Claude Code 全平台安装。

1. Plan 模式：先想清楚再动手 ​

1.1 什么时候用 ​

改动跨多个文件、方案有多种选择、或者你还没想清楚怎么做时，先进 Plan 模式。按 Shift+Tab 两次切换到 plan mode。

1.2 它做什么 ​

Plan 模式下 Claude 只读代码、搜索文件、设计方案，不修改任何文件。它会产出一份实现计划等你审批，批准后才进入执行。

1.3 实用建议 ​

  • 复杂需求先 Plan 再执行，能挡掉大部分方向性返工。
  • 计划里的每一步都可以批注修改，别客气，直接提。
  • 日常小改动不必走 Plan，避免仪式感拖慢节奏。

2. 自定义斜杠命令 ​

2.1 创建方法 ​

把常用提示词存成文件，就变成可复用的斜杠命令：

text
.claude/commands/        项目级，随仓库共享
~/.claude/commands/      用户级，所有项目可用

例如创建 .claude/commands/review.md：

markdown
审查当前未提交的改动：
1. 逐文件检查逻辑错误、边界情况和安全问题
2. 检查是否符合 CLAUDE.md 中的规范
3. 按严重程度列出问题清单

之后在会话里输入 /review 即可调用。

2.2 参数与动态内容 ​

文件里可以用 $ARGUMENTS 接收参数（/review focus on security），用 ! 前缀注入命令输出（如 !`git diff` 自动带上当前改动）。

3. Hooks：把规矩变成自动执行 ​

3.1 Hooks 是什么 ​

Hooks 是在特定事件（如每次编辑文件后、提交前）自动执行的 shell 命令，配置在 .claude/settings.json。它不靠 AI 自觉，是强制执行的。

3.2 典型用法 ​

  • 编辑代码后自动运行格式化。
  • 每次改动后自动跑 typecheck，失败立即反馈给 AI。
  • 阻止 AI 修改某些敏感文件。

3.3 示例 ​

json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "npx prettier --write \"$CLAUDE_FILE_PATHS\"" }
        ]
      }
    ]
  }
}

配置后 Claude 每次写完文件，prettier 自动格式化，AI 和你都省心。

4. MCP：给 Claude 接上外部工具 ​

4.1 MCP 是什么 ​

Model Context Protocol 是连接外部工具的标准协议。装上 MCP 服务器，Claude 就能查数据库、调浏览器、读文档、操作第三方服务。

4.2 添加方法 ​

bash
claude mcp add <名称> -- <启动命令>

例如接入 Playwright 浏览器自动化：

bash
claude mcp add playwright -- npx -y @playwright/mcp@latest

会话里用 /mcp 查看已接入的服务器状态。

4.3 值得先试的几个 ​

  • Playwright / Puppeteer：让 Claude 打开真实浏览器验证页面效果。
  • 数据库 MCP：直接查表结构和数据，写 SQL 不靠猜。
  • GitHub MCP：读写 issue 和 PR，省去来回切换。

按需接入，装太多反而占用上下文。

5. 子代理：并行干活 ​

5.1 适用场景 ​

大范围代码搜索、批量重构、多个独立子任务。主会话派活给子代理，各自独立上下文，干完汇总回来，主会话的上下文不被塞爆。

5.2 用法 ​

直接用自然语言派活即可：

text
并行做三件事：
1. 找出所有直接操作 DOM 的组件
2. 检查所有 API 调用是否都有错误处理
3. 统计还没写测试的模块

Claude 会自动拆给子代理并行执行。你也可以在 .claude/agents/ 里定义带专属提示词的子代理类型。

5.3 进阶技巧 ​

  • 探索类、审查类任务优先派子代理，主会话专注核心实现。
  • 子代理是全新上下文，派活时把背景、文件路径、期望产出说清楚。

6. 日常组合拳 ​

一套经过验证的工作流：

  1. 进 Plan 模式出方案，确认后执行。
  2. 执行中让子代理并行做搜索与审查。
  3. Hooks 自动格式化与跑检查，问题即时暴露。
  4. 高频操作沉淀为自定义命令，团队共享。
  5. 需要外部能力时接入对应 MCP。
