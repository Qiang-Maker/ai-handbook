新手从这里开始 ​

这不是一份“把所有文章都看完”的目录。你的目标是完成四次能力升级：会提问 → 会选择 → 会交付 → 会复盘。每一关都必须留下可检查的作品；看懂但做不出来，还没有过关。

第一次来，只做这三件事

  1. 用下面的自测确定起点；2. 选择一个主力工具；3. 今天完成一个 20 分钟小任务。不要先安装五个软件。

2. 四周最短学习路线 ​

2.1 第 1 周：会表达，也会怀疑 ​

学习内容：LLM、Token、上下文、结构化提示词、事实核验。

每天练习：把一个模糊任务改写为“目标 + 背景 + 约束 + 验收标准”，要求 AI 先复述需求，再给结果。

过关作品：同一个任务保留原提示词、改进版提示词、两次输出和你的对比结论。

2.2 第 2 周：选定工具并跑通环境 ​

  1. 用《工具选择器》选一个主力工具。
  2. 图形界面新手优先 VS Code + GitHub Copilot 或 Cursor。
  3. 愿意用终端可选 Claude Code、Codex CLI 或 Gemini CLI。
  4. 数据必须留在本机，阅读 Ollama 与 LM Studio。

过关作品：让工具读取一个练习目录、创建文件、执行检查，并由你确认改动内容。

2.3 第 3 周：完成一个小而完整的项目 ​

跟做《第一个 AI 编程项目》。重点不是项目多复杂，而是走完整个闭环：

text
需求 → 验收标准 → 方案 → 小步实现 → 自动检查 → 人工体验 → 复盘

过关作品：一个能运行的项目、一份 README、一条验证命令、一份已知问题清单。

2.4 第 4 周：独立排错与复盘 ​

遇到问题时，不要把一整屏报错直接丢给 AI。先用《通用排错手册》定位属于环境、认证、网络、配置、模型还是项目代码层。

过关作品：记录一次真实故障的现象、最小复现、根因、修复和防复发规则。

4. 每次向 AI 下任务的固定模板 ​

text
目标：要完成什么，以及谁会使用它。
现状：已有文件、技术栈、已尝试的方法。
范围：这次要改什么，不要改什么。
约束：平台、版本、风格、性能、安全要求。
验收：必须通过哪些命令和人工检查。
过程：先检查现状并给计划；小步修改；每步验证；最后汇总差异和风险。

不会填的字段可以写“不确定，请先检查并给出选项”，比完全省略更有效。

5. 想开发 AI 产品，走这条进阶支线 ​

完成第一个项目后，如果目标是构建 AI 应用而不只是使用编程助手，按以下顺序继续：

  1. 从《AI 应用开发》建立生产系统全景；
  2. 用《生产级 AI 应用架构》划分模型与确定性程序的职责；
  3. 在知识问答场景学习《RAG 检索增强工程》；
  4. 用《AI 评测驱动开发》建立发布门禁；
  5. 任务需要多步动态行动时，再进入《Agent 工程》专题。

过关作品不是一张架构图，而是一份包含任务定义、失败边界、评测样本、预算和回滚路径的最小技术方案。

6. 从会用到专家的分界线 ​

专家不是记住更多产品名，而是稳定做到下面五件事：

  1. 把模糊目标变成可验收任务，知道什么时候应该先澄清。
  2. 为信息选择正确来源，重要事实回到官方文档或原始数据核验。
  3. 控制改动半径，使用版本控制、小步提交和回滚点。
  4. 建立验证闭环，不把“AI 说完成了”当成完成。
  5. 沉淀可复用规则，把踩坑记录写进项目文档、检查脚本和模板。
