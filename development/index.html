AI 应用开发 ​

把模型接上 API 只完成了演示。真正的 AI 应用还要处理不确定输出、上下文选择、失败重试、质量回归、数据权限和成本上限。本专题不绑定某个模型或框架，而是讲能长期复用的工程方法。

1. 先建立正确的系统边界 ​

一个可上线的 AI 功能通常包含五层：

text
产品入口 → 业务编排 → 模型网关 → 模型服务
                ↓
       检索 / 工具 / 状态 / 评测 / 观测
  • 产品入口负责采集目标、展示过程和接收用户确认。
  • 业务编排保存状态，决定什么时候检索、调用工具或结束。
  • 模型网关统一模型选择、超时、重试、限流和用量记录。
  • 能力层提供知识、工具与长期状态，不能塞进一段无限增长的提示词。
  • 质量系统用离线评测和线上指标判断改动是否真的更好。

关键判断是：模型负责处理语义与不完整信息，程序负责确定性约束。 权限、金额计算、状态迁移和最终写入不应只靠提示词保证。

2. 推荐阅读顺序 ​

  1. 《生产级 AI 应用架构》：先理解请求链路、结构化输出、网关、降级与安全边界。
  2. 《RAG 检索增强工程》：学习如何从文档中选对证据，而不是把所有资料都塞进上下文。
  3. 《评测驱动开发》：建立数据集、评分器、回归门禁和线上反馈闭环。
  4. 《Agent 系统架构》：当任务需要多步行动，再进入状态机、工具调用与恢复机制。

3. 三种常见产品形态 ​

形态核心难题优先建设
内容生成风格、一致性、事实性模板、引用、人工审核、离线评测
知识问答找对资料并忠于证据权限过滤、混合检索、重排、拒答
任务 Agent正确行动并可恢复状态机、幂等工具、审批、轨迹观测

不要因为“Agent”更热门就把一次模型调用改造成自治循环。链路越长，成本、时延和失败组合越多；只有任务确实需要根据中间结果动态决定下一步时，Agent 才带来净收益。

4. 上线前最低标准 ​

  • 有一组来自真实场景的固定评测样本，不靠几次手工聊天判断质量。
  • 所有模型输出先做结构和业务校验，错误能被分类而非静默吞掉。
  • 外部写操作具备幂等键、权限检查、超时和审计记录。
  • 日志能关联一次用户请求中的检索、模型调用、工具调用和最终结果。
  • 设置单请求步数、Token、时间和费用预算，并有明确降级路径。
  • 敏感数据进入模型前完成最小化和授权判断。

完成这几项，AI 功能才从“能演示”进入“可运营”。
