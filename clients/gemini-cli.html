Gemini CLI 全平台安装与入门 ​

Gemini CLI 是 Google 开源的终端 AI Agent，可理解代码、编辑文件、运行命令并通过 MCP 扩展工具。适合愿意在终端工作、希望用 Google 账号快速开始的用户。

1. 安装前准备 ​

根据 Gemini CLI 官方入门文档，标准安装方式使用 npm。先确认 Node.js 与 npm：

bash
node --version
npm --version

如果两条命令都显示版本号，再继续。没有 Node.js 时，从 Node.js 官网 安装当前 LTS 版本，重新打开终端。

2. 安装与验证 ​

2.1 Windows PowerShell、macOS 与 Linux ​

bash
npm install -g @google/gemini-cli
gemini --version

不想全局安装，也可以临时运行：

bash
npx @google/gemini-cli

2.2 更新 ​

bash
npm install -g @google/gemini-cli@latest

3. 登录与认证 ​

运行：

bash
gemini

个人用户优先选择 Sign in with Google，浏览器完成授权即可。官方的认证说明显示，个人 Google 账号通常不需要配置 Cloud 项目；学校、公司或 Workspace 账号可能需要。

无浏览器环境可以使用 Gemini API Key。不要把真实密钥写入项目文件：

bash
# macOS / Linux，仅当前终端有效
export GEMINI_API_KEY="YOUR_GEMINI_API_KEY"
gemini
powershell
# Windows PowerShell，仅当前窗口有效
$env:GEMINI_API_KEY="YOUR_GEMINI_API_KEY"
gemini

4. 在练习项目中首次运行 ​

不要在包含重要文件的主目录直接练习。先建一个可删除的目录：

bash
mkdir gemini-practice
cd gemini-practice
git init
gemini

依次输入：

text
先列出当前目录内容，不要修改任何文件。
text
创建一个 README.md，写明这是 Gemini CLI 练习目录。完成后展示改动摘要。
text
检查 README.md 是否包含项目名称、用途和运行方式；缺少时补齐。

退出后检查：

bash
git diff -- README.md

5. 三个先学会的命令 ​

官方命令参考持续更新，入门先记住：

命令用途
/help查看当前版本实际支持的命令
/init分析项目并生成 GEMINI.md 项目规则
/mcp查看和管理 MCP 服务

GEMINI.md 应写项目事实与验证命令，不写空泛口号：

markdown
# 项目约定
- 修改前先阅读 README.md。
- 不改动 dist/ 和任何密钥文件。
- 完成后运行 npm test 与 npm run build。
- 最终说明修改文件、验证结果和剩余风险。

6. 权限与安全习惯 ​

  1. 第一次任务只在练习目录运行。
  2. 执行删除、安装、联网、Git 推送等命令前逐条确认。
  3. 令牌只放环境变量或系统凭据存储，不提交 .env。
  4. 修改前用 Git 建立回滚点，完成后查看 git diff。
  5. 不认识的 MCP 服务先阅读源码、权限范围与官方文档。

7. 常见问题 ​

7.1 gemini: command not found ​

关闭并重新打开终端，再检查 npm 全局目录：

bash
npm config get prefix
npm list -g --depth=0

7.2 浏览器登录后终端没有继续 ​

先输入 /auth 重新选择登录方式；远程主机或无图形界面环境改用 API Key。公司账号还要确认组织是否限制 Google Cloud 项目。

7.3 结果与项目规范不一致 ​

先运行 /init，人工精简生成的 GEMINI.md，然后在任务里写出明确的验收命令。规则文件是长期约束，当前提示词是本次任务，两者不能互相替代。

8. 完成标准 ​

  • [ ] gemini --version 能返回版本号。
  • [ ] 能在练习目录完成登录。
  • [ ] 能创建文件并用 git diff 审查。
  • [ ] 已创建不包含密钥的 GEMINI.md。
  • [ ] 知道用 /help 核对当前版本能力。
