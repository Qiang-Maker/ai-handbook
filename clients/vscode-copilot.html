VS Code 与 GitHub Copilot 入门 ​

VS Code + GitHub Copilot 适合第一次接触 AI 编程的人：文件、修改和终端都在同一个图形界面中，便于观察 AI 做了什么。Copilot Free 可用于体验，具体额度和功能以 GitHub Copilot 官方方案为准。

1. 准备账户与软件 ​

  1. 注册 GitHub 账户。
  2. 从 VS Code 官网 安装最新版。
  3. 打开一个专门的练习文件夹，不要直接用桌面或用户主目录。

按照 VS Code 官方设置指南，把鼠标移到状态栏的 Copilot 图标，选择 Use AI Features，按提示登录 GitHub。没有订阅的个人账户会进入可用的免费方案。

2. 认识三个模式 ​

根据 GitHub 官方 IDE 聊天文档，常用模式分工如下：

模式适合做什么是否改文件
Ask解释代码、查概念、定位可能原因默认不改
Plan分析复杂需求、列步骤、发现缺失信息先不实现
Agent多文件修改、运行命令、循环修复会改，需审查

新手的稳定顺序是 Ask 看懂 → Plan 定范围 → Agent 小步执行，不是所有任务直接扔给 Agent。

3. 完成第一次可审查修改 ​

3.1 建立练习文件 ​

创建 index.html，输入：

html
<!doctype html>
<html lang="zh-CN">
  <head><meta charset="UTF-8"><title>我的练习</title></head>
  <body><h1>今天开始学习 AI 编程</h1></body>
</html>

3.2 用 Ask 模式理解 ​

text
解释当前 index.html 的结构。指出一个无障碍问题和一个视觉问题，不要修改文件。

3.3 用 Agent 模式修改 ​

text
只修改 index.html：补充 viewport，增加清晰的页面结构和一个按钮。
不要引入框架或外部资源。完成后说明每处修改的理由。

在编辑器中逐段查看差异。看不懂的改动不要直接接受，可以追问“这一行为什么需要”。

3.4 人工验证 ​

用浏览器打开 index.html，检查标题、按钮、手机窗口和键盘 Tab 操作。AI 的文字说明不是验证结果，实际页面才是。

4. 给项目建立长期规则 ​

在聊天中输入 /init，让 VS Code 分析代码库并创建自定义项目指令。官方指南说明该命令会根据项目生成适配的说明；生成后仍需人工检查。

规则至少包含：

markdown
- 技术栈与版本
- 目录职责和禁止修改目录
- 命名、格式和语言规范
- 测试、类型检查、构建命令
- 完成任务时的汇报格式

不要把密码、令牌、内部地址写进规则文件。

5. 一套日常工作流 ​

  1. 同步现状：打开正确文件夹，确认 Git 状态干净。
  2. 先问后改：让 Ask 模式解释相关模块和风险。
  3. 限定范围：写明允许修改的文件与禁止事项。
  4. 小步执行：一次只完成一个可验证目标。
  5. 审查差异：在 Source Control 面板逐文件查看。
  6. 运行验证：测试、类型检查、构建和人工体验都要做。
  7. 保留回滚点：确认无误后再提交 Git。

6. 隐私与额度 ​

VS Code 官方设置页说明，可以在设置中调整遥测和代码建议相关选项。工作或学校账户还可能受组织策略约束。开始前确认：

  • 当前登录的是个人账户还是组织账户。
  • 项目是否允许发送到云端模型。
  • Agent 将执行哪些终端命令和外部调用。
  • 当前模型或模式会消耗多少方案额度。

敏感项目应先遵守组织政策；必须离线时，使用《Ollama 与 LM Studio》中的本地方案。

7. 常见问题 ​

7.1 看不到 Copilot 图标 ​

先更新 VS Code，确认未设置 chat.disableAIFeatures，再检查扩展与 GitHub 登录状态。

7.2 Agent 不运行命令 ​

确认选择的是 Agent 模式，并检查工作区信任与工具权限。不要为了省一次确认而对陌生项目长期开放全部权限。

7.3 修改越来越乱 ​

停止继续追问，撤销到最近一个可运行状态。把任务缩小为一个文件或一个行为，并明确验收命令后重新开始。

8. 完成标准 ​

  • [ ] 已登录 GitHub，能打开 Copilot Chat。
  • [ ] 能解释 Ask、Plan、Agent 的区别。
  • [ ] 完成一次小修改并逐行审查差异。
  • [ ] 用浏览器或测试命令实际验证结果。
  • [ ] 知道在哪里撤销改动与查看 Git 差异。
