第一个 AI 编程项目 ​

你将让 AI 帮你制作一个离线任务清单：能新增、完成、筛选和保存任务。项目只用 HTML、CSS 和 JavaScript，不需要框架、账户或服务器。真正的学习目标是掌握可重复的交付流程。

1. 最终验收标准 ​

开始前先写“怎么算完成”，防止 AI 边做边扩大范围。

text
功能：新增任务；切换完成状态；删除任务；全部/未完成/已完成筛选。
数据：刷新页面后仍保留，使用 localStorage。
界面：手机 360px 宽可用；键盘能操作；有空状态。
限制：只用原生 HTML/CSS/JS；不加载外部库；不请求网络。
质量：控制台无报错；README 写清运行、测试和已知限制。

2. 建立安全练习目录 ​

bash
mkdir ai-todo-practice
cd ai-todo-practice
git init
printf "# AI Todo Practice\n" > README.md
git add README.md
git commit -m "chore: initialize practice project"

如果 Git 要求身份信息，按终端提示设置姓名和邮箱；暂时也可以跳过提交，但必须保留单独练习目录。

3. 第一轮只让 AI 做计划 ​

在你选定的 AI 编程工具中打开该目录，发送：

text
你正在一个新的练习项目中。阅读 README.md 和目录结构，不要修改文件。
目标：实现离线任务清单。
约束和验收标准如下：[粘贴第 1 节]
请输出：文件方案、数据结构、实现顺序、每一步的验证方法、需要我决定的问题。

检查计划是否只包含 index.html、style.css、app.js 和 README.md。如果它引入框架、数据库或构建工具，要求删掉这些超出范围的内容。

4. 分四步实现 ​

4.1 先做静态结构 ​

text
只完成第 1 步：创建 index.html 的语义化结构和空状态。
先不要写 CSS 和 JavaScript。完成后说明如何用浏览器人工检查。

检查页面能打开，标题、输入框、按钮、筛选区、列表区存在。

4.2 再做核心逻辑 ​

text
只创建 app.js，实现新增、完成、删除和筛选。
任务对象使用 id、text、completed、createdAt。
所有按钮必须可通过键盘操作。不要修改样式。
完成后列出我应该手工执行的 8 个测试步骤。

按它列出的步骤逐项测试，至少覆盖空输入、重复点击、删除与刷新。

4.3 加入本地保存 ​

text
为现有逻辑加入 localStorage 持久化。
读取数据时处理格式错误：损坏数据不能让页面崩溃。
不要改变现有交互。完成后说明存储键名和错误处理路径。

在浏览器开发者工具的 Application / Storage 面板查看数据。再手动把值改成错误 JSON，刷新后页面应恢复为空状态而不是白屏。

4.4 最后做视觉与响应式 ​

text
只修改 style.css，让页面在 360px 手机和桌面宽度下都清晰可用。
要求：明显的键盘焦点、足够的颜色对比、完成任务不能只靠颜色区分。
不使用外部字体、图片或 CSS 框架。

把浏览器调到 360px 宽，用 Tab 走遍所有控件，并检查缩放到 200% 时内容没有被遮挡。

5. 做一次“破坏性测试” ​

不要只验证顺利路径。人工执行：

  1. 输入全是空格的任务。
  2. 连续快速点击新增。
  3. 新增 50 个任务后筛选。
  4. 使用很长的中文和英文混合文本。
  5. 完成任务后刷新页面。
  6. 删除当前筛选结果中的最后一项。
  7. 修改 localStorage 为无效内容再刷新。
  8. 只用键盘完成新增、勾选和删除。

把失败现象单独发给 AI，一次修一个：

text
最小复现：在“未完成”筛选下删除最后一项。
预期：显示空状态。
实际：列表区域为空但空状态没有出现，控制台无报错。
请先定位原因，只做解决这个问题的最小修改，并说明验证步骤。

6. 让 AI 审查，但由你决定 ​

text
审查当前项目，不要修改文件。按严重程度列出：
1. 功能错误；2. 数据丢失风险；3. 无障碍问题；4. 不必要复杂度。
每项给出证据、复现步骤和最小修复建议。没有证据的不要猜。

审查结果不必全改。优先处理能复现的功能与数据问题；“可以进一步抽象”通常不是小项目的优先事项。

7. 完成 README 与交付检查 ​

让 AI 更新 README，必须包含：

markdown
# 项目名称
## 功能
## 运行方式
## 人工测试清单
## 数据存储与清除方法
## 已知限制
## 项目结构

最后运行：

bash
git status
git diff --check
git diff

git diff --check 无输出通常表示没有空白字符错误；仍要阅读完整差异。确认后提交：

bash
git add index.html style.css app.js README.md
git commit -m "feat: build offline task list"

8. 项目复盘 ​

写下四个答案：

  1. 哪条要求最容易被 AI 忽略？
  2. 哪个错误是通过测试发现，而不是看代码发现？
  3. 哪一步返工最多，能否在验收标准中提前避免？
  4. 下个项目要写进规则文件的三条约定是什么？

能独立回答这些问题，才算完成本教程。下一步可以把项目换成你真正需要的小工具，但继续沿用同一个闭环。
